# 01 · 数据库在做什么？

> 约 10 分钟 · 无需任何环境 · 先建立直觉

这一课不碰 Doris，先回答一个更根本的问题：**数据库到底是干什么的？**
答案想清楚了，后面所有概念都会有地方放。

## 从一个你熟悉的场景开始

假设你维护着一份《资产台账》Excel：每一行是一台服务器，列有机房、IP、责任人、状态。

人少、数据少的时候，Excel 完全够用。但迟早会遇到三个坎：

1. **改不动**：几万台设备，打开文件就要转圈；
2. **不敢一起改**：你和同事同时编辑，后保存的人把先保存的覆盖了；
3. **查不动**：领导随口一问“上个月各系统新增了多少条告警”，你只能一列列筛。

数据库就是为这三件事生的：**放得下有组织的大量数据，撑得住多人同时使用，答得上各种条件的提问。**

把数据库想成一个**专门的档案库房 + 一位永远不下班的库管员**：

- 库房里的货架按规则摆放（这就是“数据结构”）；
- 你不用自己爬梯子找，把问题写给库管员（这就是 SQL）；
- 库管员有办法在几万卷档案里迅速找出答案（这就是“查询引擎”）。

## 最小的三个概念：表、行、列

数据库里最基础的组织方式叫**表（Table）**，和你熟悉的 Excel 几乎一一对应：

- **列（Column）**：描述一条数据的字段，比如 IP、责任人；
- **行（Row）**：一条具体的数据，比如某一台服务器；
- 在建表时还可以指定其中几列为 **Key 列**（用来标识、排序），其余是 Value 列。

## SQL 是“提问的语言”

你不需要学编程才能看懂 SQL，它就是一句条件明确的中文：

```sql
SELECT 系统名称, COUNT(*) AS 告警数
FROM 监控告警表
WHERE 日期 >= '2026-10-01'
GROUP BY 系统名称;
```

逐句翻译：**从**监控告警表里，**筛出** 10 月以来的记录，**按**系统名称分组，**数出**每套系统有几条。

数据库的工作，就是读懂这句话，然后从可能上百万行的数据里快速给出结果。

## 两种脾气的数据库：记账的 vs 出报表的

数据库大致分两类，干的活完全不同：

| | 交易型（OLTP） | 分析型（OLAP） |
|---|---|---|
| 典型动作 | 插入一条订单、改一个状态 | 统计一个月的总数、对比趋势 |
| 数据范围 | 一次几行 | 一次几百万行 |
| 关心的事 | 不能丢、不能错、立刻生效 | 扫得快、算得快 |
| 身边的例子 | CMDB 后台、工单系统 | 报表平台、监控大盘 |

**Doris 属于右边这一类**：它是一套面向分析场景的数据库，官方定位是“基于 MPP 架构的高性能、实时分析型数据库”，擅长在海量数据上亚秒级返回汇总结果。

> 这也解释了为什么运维团队会引入它：资产台账、监控告警、运行日报这类“汇总分析”需求，恰恰是分析型数据库的主场。
