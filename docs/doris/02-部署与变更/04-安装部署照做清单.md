# 安装部署照做清单（零基础 · 1FE + 1BE）

> 配套官方文档：[手动部署存算一体集群](https://doris.apache.org/zh-CN/docs/4.x/install/deploy-manually/integrated-storage-compute-deploy-manually/)（2026-05 更新）、[操作系统检查](https://doris.apache.org/zh-CN/docs/4.x/install/preparation/os-checking/)（2026-05 更新）。
> 官方文档给的是"要点"，这份清单把它拆成可以逐条打勾的动作。**每条都按同一个格式写：做什么 → 为什么 → 命令 → 期望结果 → 不对怎么办。**
> 目标机器：1 台 Linux 测试机（CentOS 7+ / Ubuntu 22.04+），装 1 个 FE + 1 个 BE。
> 预计耗时：2–3 小时（其中下载 3.8 GB 安装包是大头）。

::: tip 怎么用这份清单
不要跳步。每一步的命令执行完，先对照「期望结果」确认对了，再进下一步。
出错了先看该步的「不对怎么办」，再去第 9 节的报错对照表。
:::

## 0. 开工前，先把 4 件事想明白

### 0.1 这次部署到底要达成什么

一句话：让一台机器上跑起一个「大脑（FE）」+ 一个「干活的（BE）」，并且你能用 mysql 客户端连进去、建表、插入、查出来。

**验收标准（4 条全绿才算做完）**：

1. `SHOW FRONTENDS;` 里 Alive=true、Join=true、IsMaster=true
2. `SHOW BACKENDS;` 里 Alive=true
3. 自己建的库表能插入数据、能 select 出来
4. root 的空密码已经改掉

为什么要先定验收标准：不然后面看到一堆 true/false 也不知道什么算成功。

### 0.2 三个变量，后面所有命令都用它们

| 变量 | 含义 | 本文示例值 | 怎么查你自己的 |
|---|---|---|---|
| `<IP>` | 这台机器的**内网** IP | `192.168.88.30` | `hostname -I` 或 `ip addr` |
| `<DORIS_HOME>` | 解压后的 doris 目录 | `/opt/doris/apache-doris-4.0.8-bin-x64` | 解压完就有 |
| `<JAVA_HOME>` | JDK 17 安装路径 | `/usr/lib/jvm/java-17-openjdk` | `readlink -f $(which java)` 后去掉 `/bin/java` |

::: warning 为什么不能用 localhost / 127.0.0.1
Doris 的 FE 和 BE 之间靠**网络 IP + 端口**互相识别。配置里写 127.0.0.1，看似单机能连，但一旦你换了网卡、加了网卡，或者 BE 注册时 FE 记录的是 127.0.0.1，另一侧用真实 IP 去连就连不上，表现为「BE 一直 Alive=false」。
所以从第一天起就写**真实的网卡 IP**。
:::

### 0.3 端口地图（必须认识这 8 个端口）

| 组件 | 端口 | 名字 | 干什么用 |
|---|---|---|---|
| FE | 9030 | query_port | **MySQL 协议**，你用 mysql 客户端连的就是它 |
| FE | 8030 | http_port | Web UI（浏览器看集群状态） |
| FE | 9010 | edit_log_port | FE 之间同步元数据（多 FE 时用） |
| FE | 9020 | rpc_port | FE 内部 RPC |
| BE | 9050 | heartbeat_service_port | **心跳**，BE 向 FE 报活；`ADD BACKEND` 里写的也是这个端口 |
| BE | 9060 | be_port | BE 的 thrift 服务端口，FE 下发查询用 |
| BE | 8060 | brpc_port | BE 之间的数据传输（副本同步） |
| BE | 8040 | webserver_port | BE 的 Web UI |

为什么必须认识：**90% 的"注册不上 / 连不上"都是这几个端口被防火墙挡了，或者被别的程序占了。**

### 0.4 启动顺序与依赖关系

```text
1. 启动 FE（大脑先醒）
2. 在 FE 里注册 BE 的地址（告诉大脑"有个干活的要来了"）
3. 启动 BE（干活的醒来，主动向 FE 发心跳）
4. BE 心跳成功 → Alive=true → 集群可用
```

顺序反了（先启 BE 后注册）也**不会坏**，BE 会一直重试注册；但排查问题时你会分不清是"没注册"还是"注册了但连不上"，所以照官方顺序做。

## 1. 环境检查（8 项，一次做完）

做完这 8 项再做后面所有事。每项都很短，但少一项后面就会卡住。

### 1.1 确认系统版本、CPU 架构、是否支持 avx2

```bash
cat /etc/os-release        # 看系统版本，要求 CentOS 7+ / Ubuntu 22.04+
uname -m                   # x86_64 或 aarch64
grep -o 'avx2' /proc/cpuinfo | head -1
```

**期望结果**：

- `uname -m` 输出 `x86_64` → 下 **x64** 包；输出 `aarch64` → 下 **ARM64** 包
- 最后一条命令输出 `avx2` → 可以下 **x64 (avx2)** 包；**什么都没输出** → 必须下 **x64 (no avx2)** 包

**为什么**：4.x 的 x64 包分成 avx2 和 no-avx2 两种构建。老 CPU（比如 2013 年前的 Xeon）用 avx2 包，进程会直接 `Illegal instruction (core dumped)` 崩掉，日志里看不出原因，非常难查。

### 1.2 关闭 swap

```bash
sudo swapoff -a
sudo sed -ri 's/^([^#].*\sswap\s.*)$/#\1/' /etc/fstab   # 注释掉 fstab 里的 swap 行，重启后也生效
free -h                                                  # 确认 Swap 一行为 0
```

**为什么**：数据库希望内存可控。一旦内存被换到磁盘，查询延迟会突然抖到几百毫秒，且很难定位。

### 1.3 关闭透明大页（THP）

```bash
echo madvise | sudo tee /sys/kernel/mm/transparent_hugepage/enabled
echo madvise | sudo tee /sys/kernel/mm/transparent_hugepage/defrag
cat /sys/kernel/mm/transparent_hugepage/enabled    # 期望：[madvise] never
```

**为什么**：THP 会让内存分配出现不可预测的停顿和碎片，Doris 官方明确要求关掉。

### 1.4 增大虚拟内存区域

```bash
echo 'vm.max_map_count = 2000000' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
sysctl vm.max_map_count        # 期望：vm.max_map_count = 2000000
```

**为什么**：Doris 会打开大量数据文件并做 mmap。这个值太小，运行一段时间就报 `Too many open files` 或 mmap 失败，看起来像"内存不够"，其实是内核限制。

### 1.5 增大文件句柄数

```bash
echo '* soft nofile 1000000' | sudo tee -a /etc/security/limits.conf
echo '* hard nofile 1000000' | sudo tee -a /etc/security/limits.conf
# 重新登录（或开一个新终端）后验证：
ulimit -n                      # 期望：1000000
```

**为什么**：BE 每个 tablet 都是独立文件，几万个文件很正常。默认 1024 个句柄，建几张表就爆。

::: warning 如果 ulimit -n 还是 1024
说明你还在旧会话里。**退出 SSH 重新登录**再执行。若仍不变，检查 `/etc/security/limits.d/` 下有没有 `20-nproc.conf` 之类的文件把值覆盖了。
:::

### 1.6 网络连接溢出时立即重置

```bash
echo 'net.ipv4.tcp_abort_on_overflow = 1' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

**为什么**：高并发下 accept 队列满了，默认行为是"悄悄丢掉再重试"，客户端会卡住几十秒。开启后连接立刻失败，客户端能快速重连，问题也暴露得早。

### 1.7 关闭防火墙（测试机）

```bash
# CentOS / RHEL
sudo systemctl stop firewalld
sudo systemctl disable firewalld
sudo getenforce                      # 若输出 Enforcing，执行下一行
sudo setenforce 0

# Ubuntu
sudo ufw status
sudo ufw disable
```

**为什么**：FE 与 BE 之间要互相连 9010/9020/9050/9060/8060，只要有一个不通，表现就是"BE 起不来 / Alive=false / FE 加不进去"。测试机直接关最省事；生产环境改成按 0.3 端口表精确放行。

### 1.8 时间同步（单机也要做）

```bash
timedatectl                      # 看 System clock synchronized: yes
# CentOS
sudo systemctl enable --now chronyd
# Ubuntu
sudo systemctl enable --now systemd-timesyncd
chronyc tracking 2>/dev/null || timedatectl
```

**为什么**：多 FE 部署时，节点间时间差超过 **5 秒**，新 FE 会被拒绝加入集群（日志里是 clock / delta 相关报错）。单机虽然不涉及，但先把习惯养成，后面加节点不用回头改。

## 2. 创建用户与目录

### 2.1 建一个专用的 doris 用户

```bash
sudo useradd -m -s /bin/bash doris
sudo passwd doris          # 设置一个密码，按提示输两次
su - doris                 # 切到 doris 用户，后面所有操作都在这个身份下做
```

**为什么不用 root**：

- FE/BE 会在自己的目录里大量读写，用 root 跑出来的文件权限是 600/root，以后想用 doris 用户启动就报"没有权限"；
- 官方明确建议用独立用户，避免影响系统目录。

### 2.2 规划三个目录（并在 doris 身份下创建）

```bash
sudo mkdir -p /opt/doris          # 程序目录
sudo mkdir -p /data/doris-meta    # FE 元数据（账本）
sudo mkdir -p /data/doris-storage # BE 数据（真正的数据文件）
sudo chown -R doris:doris /opt/doris /data
df -h /data                       # 确认空间：测试机 50G 以上够用
```

**为什么分成三个目录**：

- `doris-meta` 存的是整个集群的**元数据**（有哪些库、哪些表、哪些 BE、数据分布在哪）。它丢了，数据文件还在也认不出来，等于集群没了。所以要单独放、优先放 SSD、方便单独备份；
- `doris-storage` 是 BE 的数据目录，IO 最重；
- 程序目录升级时会被整体替换，不能和上面两个混在一起。

::: tip 官方推荐
生产环境把元数据放在独立 SSD 上（官方建议 FE 盘 100GB+、BE 盘 500GB+）。测试机同一块盘也可以，知道"故障域是同一个"就行。
:::

## 3. 安装 JDK 17

### 3.1 先看系统里有没有

```bash
java -version           # 可能提示 command not found，正常
ls /usr/lib/jvm/        # 看有没有现成的 JDK
```

### 3.2 安装 JDK 17

```bash
# CentOS 7 / 8
sudo yum install -y java-17-openjdk java-17-openjdk-devel

# Ubuntu 22.04+
sudo apt-get update && sudo apt-get install -y openjdk-17-jdk
```

### 3.3 找到 JAVA_HOME 并记住

```bash
readlink -f $(which java)
```

**期望结果**：类似 `/usr/lib/jvm/java-17-openjdk-17.0.9.0.9-1.el7_9.x86_64/bin/java`

把结尾的 `/bin/java` 去掉，就是 `JAVA_HOME`，例如：

```text
/usr/lib/jvm/java-17-openjdk-17.0.9.0.9-1.el7_9.x86_64
```

**为什么必须 17+**：4.x 的代码用 JDK 17 编译。用 JDK 8 启动会报 `Unsupported class file major version 61`，FE 直接起不来。这是 2.x 老教程最容易带偏你的地方（那时候要求 JDK 8）。

::: warning 不要用系统自带的 JDK 8 凑合
即使系统已经有 java 8 并且 `java -version` 正常，Doris 4.x 也跑不起来。必须另装 17，并在配置文件里通过 `JAVA_HOME` 指过去，不要依赖系统默认。
:::

## 4. 下载与解压

### 4.1 先决定版本

| 分支 | 当前版本 | 定位 | 建议 |
|---|---|---|---|
| 4.1 | 4.1.5 | Latest（最新功能） | 想跟新特性就选它 |
| 4.0 | 4.0.8 | Stable（稳定维护线） | **你现在学的 4.0.7 属于这条线，升补丁版本不迁移数据，建议选 4.0.8** |

补丁版本（4.0.7 → 4.0.8）之间数据双向兼容，直接换包即可，本文按 **4.0.8** 写。官方下载页：<https://doris.apache.org/zh-CN/download/>

### 4.2 下载（3.8 GB，建议用断点续传）

```bash
cd /opt/doris
# x64 (avx2) 包：
sudo -u doris wget -c https://apache-doris-releases.oss-accelerate.aliyuncs.com/apache-doris-4.0.8-bin-x64.tar.gz
# 顺便下校验文件：
sudo -u doris wget -c https://apache-doris-releases.oss-accelerate.aliyuncs.com/apache-doris-4.0.8-bin-x64.tar.gz.sha512
```

- ARM 机器把文件名里的 `x64` 换成 `arm64`；
- CPU 不支持 avx2 的，下载页上选 **x64 (no avx2)** 的包，文件名以后缀区分，以页面显示为准；
- 下载中断了就**再执行一次同一条命令**，`-c` 会接着下。

### 4.3 校验完整性（别跳过）

```bash
cd /opt/doris
cat apache-doris-4.0.8-bin-x64.tar.gz.sha512      # 看看文件内容长什么样
sha512sum apache-doris-4.0.8-bin-x64.tar.gz       # 算出来，和上面对比
```

**期望结果**：两个哈希值完全一致。

**为什么**：3.8 GB 传输中断过、被公司安全设备改写过都可能发生。包损坏的表现是解压报错或启动时类文件缺失，非常难查，30 秒的校验能省 2 小时排查。

### 4.4 解压并认识目录

```bash
cd /opt/doris
sudo -u doris tar -xzf apache-doris-4.0.8-bin-x64.tar.gz
ls apache-doris-4.0.8-bin-x64
```

**期望结果**：看到 `fe`、`be` 两个目录。

```text
apache-doris-4.0.8-bin-x64/
├── fe/
│   ├── bin/      # 启停脚本 start_fe.sh / stop_fe.sh
│   ├── conf/     # 配置文件 fe.conf  ← 你要改的
│   └── log/      # 日志 fe.log / fe.out ← 出问题先看这里
└── be/
    ├── bin/      # start_be.sh / stop_be.sh
    ├── conf/     # be.conf ← 你要改的
    └── log/      # be.log / be.out
```

从此刻起，本文的 `<DORIS_HOME>` 就是 `/opt/doris/apache-doris-4.0.8-bin-x64`。**升级时只换这个目录名，配置和数据的路径不要动。**

::: tip 小技巧
可以建个软链接固定路径，以后升级不用改脚本：
`ln -s /opt/doris/apache-doris-4.0.8-bin-x64 /opt/doris/current`
之后统一用 `/opt/doris/current` 访问。
:::

## 5. 部署 FE（Master，第一个也是唯一一个 FE）

### 5.1 先算出你的 priority_networks

```bash
ip -4 addr show | grep -w inet
```

**期望结果**：找到你那张业务网卡的那一行，形如：

```text
inet 192.168.88.30/24 brd 192.168.88.255 scope global eth0
```

- `192.168.88.30` 就是你的 `<IP>`
- `/24` 就是掩码长度
- 那么 `priority_networks = 192.168.88.0/24`（**前 3 段保留，最后一段写 0**）

**为什么这一步不能省**：FE 启动时会枚举本机**所有**网卡 IP（物理网卡、docker0、虚拟网卡、127.0.0.1…），它需要知道"对外用哪个"。`priority_networks` 就是筛选条件：只有落在这个网段里的 IP 才会被选为对外地址。

不写或写错会发生什么：

- 多网卡机器上选到 `172.17.0.1`（docker0）或 `127.0.0.1`，FE 自认为地址是它，于是 BE 注册时用的真实 IP 跟 FE 记的对不上，**BE 永远 Alive=false**；
- 匹配不到任何网卡时，FE 启动直接失败，`fe.out` 里是 `Failed to find enough ports` 之类的迷惑报错。

::: tip 简单记法
`priority_networks` 填的**不是你自己的 IP**，是**你所在网段**。IP 最后一段归零，斜杠后写掩码位数。
:::

### 5.2 改 fe.conf 的 5 个参数

```bash
cd /opt/doris/apache-doris-4.0.8-bin-x64/fe
cp conf/fe.conf conf/fe.conf.bak      # 改坏了能还原，养成习惯
vi conf/fe.conf
```

在文件里**找到对应行修改**（没有就新增到文件末尾），改完是这 5 行：

```properties
JAVA_HOME = /usr/lib/jvm/java-17-openjdk-17.0.9.0.9-1.el7_9.x86_64
priority_networks = 192.168.88.0/24
meta_dir = /data/doris-meta
lower_case_table_names = 1
JAVA_OPTS = -Xmx4096m -XX:+UseG1GC
```

逐个说清楚为什么要改：

| 参数 | 为什么 | 不改会怎样 |
|---|---|---|
| `JAVA_HOME` | 让 Doris 用你装的 JDK 17，而不是系统默认的 java | 系统默认是 8 就直接起不来；即使能起，也不是你以为的那个版本 |
| `priority_networks` | 指定 FE 对外用哪个网段 | 多网卡选错 IP，BE 永远注册不上 |
| `meta_dir` | 元数据放到独立目录，方便备份、避免升级时被覆盖 | 默认在安装目录的 `doris-meta` 下，升级换目录就被带走了 |
| `lower_case_table_names` | 表名大小写不敏感，跟 MySQL 习惯一致 | **集群创建后不能再改**，先想清楚；默认值 0 表示区分大小写，以后写 SQL 容易踩坑 |
| `JAVA_OPTS` | 限制 FE 的 JVM 堆大小 | 默认值按机器内存给，小内存机器（8G 以下）可能被撑爆 OOM |

::: warning JAVA_OPTS 不要写两行
`fe.conf` 里本来就有一行 `JAVA_OPTS = ...`。**修改它，不要新增第二行**——Doris 读取时后面的会覆盖前面的，你以为改生效了其实没有。不确定就执行：

```bash
grep -n "JAVA_OPTS\|JAVA_HOME\|priority_networks\|meta_dir\|lower_case_table_names" conf/fe.conf
```

每个参数应该只出现（未注释的）一次。
:::

::: tip 内存怎么给
测试机 8G 内存，给 `-Xmx4096m`；16G 给 `-Xmx8192m`。官方生产建议 16G 以上。指不要让 FE 吃满整机内存，BE 也要留。
:::

### 5.3 启动 FE

```bash
cd /opt/doris/apache-doris-4.0.8-bin-x64/fe
bin/start_fe.sh --daemon
```

`--daemon` 表示后台运行，命令立刻返回、没有输出，**这是正常的**。

**立刻做三步确认**：

```bash
# 1. 端口是否在监听（9030 是 mysql 端口，8030 是 Web UI）
ss -lntp | grep -E '9030|8030'

# 2. 日志末尾有没有异常
tail -n 30 log/fe.log
tail -n 30 log/fe.out

# 3. 浏览器打开 http://<IP>:8030 ，能看到 Doris 的 Web 界面
```

**期望结果**：9030 和 8030 都在监听；`fe.out` 里没有 `Exception`、`Error` 字样。

**不对怎么办**：

| 现象 | 原因 | 处理 |
|---|---|---|
| 命令没反应，`ss` 里看不到 9030 | 启动瞬间失败 | 看 `log/fe.out`，90% 是 `JAVA_HOME` 写错或 JDK 版本不对 |
| `fe.out` 里 `Unsupported class file major version` | 用了 JDK 8/11 | 重装 JDK 17，改 `JAVA_HOME` |
| `Address already in use` | 端口被占 | `ss -lntp \| grep 9030` 找出进程，`kill` 掉或改端口 |
| `Permission denied` 写 `/data/doris-meta` | 目录属主不是 doris | `sudo chown -R doris:doris /data/doris-meta` |
| 起了一下又停了，日志里 `priority_networks` 相关报错 | 网段写错 | 回到 5.1 重新算 |

### 5.4 装 mysql 客户端并连接

Doris 兼容 MySQL 协议，但安装包里不自带客户端，需要系统装一个：

```bash
# CentOS
sudo yum install -y mariadb
# Ubuntu
sudo apt-get install -y mysql-client
```

连接（root 初始密码为空，直接回车）：

```bash
mysql -uroot -P9030 -h192.168.88.30
```

**期望结果**：进入 `mysql>` 提示符，出现 Doris 的欢迎信息。

::: tip 连不上先分两种情况
- `Can't connect to MySQL server on '<IP>'` → 网络/端口/防火墙问题，先用 `ss` 确认 9030 在监听；
- `Access denied` → 密码问题（初始为空，别乱填）。
:::

### 5.5 判定 FE 是否真正就绪

```sql
SHOW FRONTENDS\G
```

**期望结果**（看 3 个字段）：

```text
Alive: true          -- 进程活着，且在发心跳
Join: true           -- 已经加入集群（注意：Join=true 不代表现在还活着）
IsMaster: true       -- 它是 Master
Role: FOLLOWER       -- 单 FE 时它自己既是 Master 又占一个 Follower 槽位
Version: 4.0.8-xxx   -- 确认装的是你要的版本
```

三项全 true 才算这一步完成，**才可以往下做 BE**。

**为什么先看 Join 再看 Alive**：`Join=true, Alive=false` 的典型含义是"节点曾经加入过集群，但现在失联了"——这正是后面排查 BE 状态的思路。

## 6. 部署 BE（干活的节点）

### 6.1 改 be.conf

```bash
cd /opt/doris/apache-doris-4.0.8-bin-x64/be
cp conf/be.conf conf/be.conf.bak
vi conf/be.conf
```

改这 3 行（同样：找到原行修改，不要重复添加）：

```properties
JAVA_HOME = /usr/lib/jvm/java-17-openjdk-17.0.9.0.9-1.el7_9.x86_64
priority_networks = 192.168.88.0/24
storage_root_path = /data/doris-storage,medium:HDD
```

| 参数 | 为什么 | 说明 |
|---|---|---|
| `JAVA_HOME` | BE 的部分功能（如 JDBC 外表）也要 Java | 和 FE 用同一个 17 |
| `priority_networks` | BE 也要选对网卡，才能让 FE 用心跳连上你 | **必须和 FE 的网段一致**，两边不一致是最常见的注册失败原因 |
| `storage_root_path` | 数据目录，以及盘的类型 | 格式：`路径,medium:HDD`；SSD 写 `medium:SSD`；多块盘用分号隔开：`/disk1/doris,medium:HDD;/disk2/doris,medium:SSD` |

**为什么要写 medium（介质）**：Doris 建表时可以指定存储介质（冷热分层）。标了介质，FE 才知道哪些盘适合放大表、哪些放冷数据。不写默认按 HDD 处理，单机测试没影响，但习惯先写对。

### 6.2 在 FE 里注册这个 BE（先注册，再启动）

```sql
-- 在刚才的 mysql 会话里执行
ALTER SYSTEM ADD BACKEND "192.168.88.30:9050";
```

**期望结果**：`Query OK, 0 rows affected`。

**为什么用 9050**：9050 是 BE 的心跳端口，FE 靠它来判断这个 BE 活没活。写成别的端口（比如 9030、9060）就会注册成功但永远心跳不上。

**为什么先注册在启动**：FE 的元数据里要先有"这台 BE 属于我"的记录，BE 启动后的第一次心跳才能被正确匹配，状态立刻从 false 变 true。反过来的顺序也能成，但会经历一段"BE 起了但 FE 不认识"的迷惑期。

::: warning 注册错了怎么删
写错 IP 或端口时，用 `ALTER SYSTEM DROP BACKEND "192.168.88.30:9051";` 删掉再重新 ADD。
:::

### 6.3 启动 BE

```bash
cd /opt/doris/apache-doris-4.0.8-bin-x64/be
bin/start_be.sh --daemon
```

同样三步确认：

```bash
ss -lntp | grep -E '9050|9060|8040|8060'    # 四个端口都应在监听
tail -n 30 log/be.log
tail -n 30 log/be.out
curl http://192.168.88.30:8040/api/health   # 期望返回 OK
```

`curl` 那行返回 `OK` 说明 BE 自己的 Web 服务是健康的。

### 6.4 判定 BE 是否就绪

```sql
SHOW BACKENDS\G
```

**期望结果**：

```text
Alive: true                       -- 关键：必须是 true
SystemDecommissioned: false       -- 没有被杀掉/下线
TabletNum: 0                      -- 新节点还没数据，正常
StorageMedium: HDD
Version: 4.0.8-xxx
LastHeartbeat: ...                -- 时间在几秒内刷新
```

**Alive=false 怎么办**（按顺序查，命中率从高到低）：

1. **等 10 秒再查一次**——心跳是周期性的，刚启动可能有几秒延迟；
2. `be.log` 里搜 `heartbeat` / `register`，看有没有连不上 FE 的报错；
3. 检查 `be.conf` 的 `priority_networks` 和 FE 是否同一网段（最常见）；
4. 从 BE 机器上测端口：`telnet <FE_IP> 9030`、`telnet <BE_IP> 9050`；
5. 检查 `ADD BACKEND` 里的 IP:端口 是否和 BE 实际监听的完全一致（`ss -lntp | grep 9050` 能看到绑定在哪个 IP 上）；
6. 如果注册信息确实错了：`ALTER SYSTEM DROP BACKEND "<IP>:9050";` 后重新 ADD。

::: tip LastHeartbeat 一直在变但 Alive=false
这种情况通常是元数据里记录的历史状态没更新，`DROP BACKEND` + 重新 `ADD BACKEND` 一次即可。
:::

## 7. 端到端验收（这一步做完才算部署成功）

### 7.1 建库、建表、插数据、查数据

```sql
CREATE DATABASE demo;
USE demo;

CREATE TABLE t1 (
  k1 INT,
  k2 VARCHAR(20)
)
DISTRIBUTED BY HASH(k1) BUCKETS 1
PROPERTIES ("replication_num" = "1");

INSERT INTO t1 VALUES (1, 'a'), (2, 'b'), (3, 'c');
SELECT * FROM t1;
```

**期望结果**：查出 3 行。

::: warning 为什么必须写 replication_num = "1"
Doris 默认副本数是 **3**（生产要三副本）。你现在只有 1 个 BE，副本放不下 3 份，建表会报：

```text
Failed to find enough host with storage medium and tag
```

这不是"集群坏了"，是"你只有一个 BE 却要三副本"。**单机测试一律显式写 1**，生产环境才用 3。
:::

### 7.2 改掉 root 空密码（必做）

```sql
SET PASSWORD = PASSWORD('Doris@2026#Test');
```

改完**退出重连**验证：

```bash
mysql -uroot -p -P9030 -h192.168.88.30
```

::: warning 忘了密码怎么办
在 FE 所在机器上用 `mysql -h127.0.0.1 -P9030 -uroot` 免密登录（本机回环不受密码限制），再 `SET PASSWORD = PASSWORD('新密码');`。
:::

### 7.3 确认版本与整体状态

```sql
SELECT version();
SHOW FRONTENDS\G
SHOW BACKENDS\G
```

**收工标准**：0.1 节那 4 条验收标准全部满足。

## 8. 日常启停（记住顺序）

```bash
# 停止：先 BE 后 FE（先让干活的退场，大脑最后一个走）
cd /opt/doris/apache-doris-4.0.8-bin-x64/be && bin/stop_be.sh
cd /opt/doris/apache-doris-4.0.8-bin-x64/fe && bin/stop_fe.sh

# 启动：先 FE 后 BE
cd /opt/doris/apache-doris-4.0.8-bin-x64/fe && bin/start_fe.sh --daemon
cd /opt/doris/apache-doris-4.0.8-bin-x64/be && bin/start_be.sh --daemon
```

**为什么顺序相反**：BE 启动后要向 FE 注册心跳，FE 不在就只能一直重试；停止时反过来，让 FE 先知道 BE 要走了，元数据状态更干净。

::: tip 测试机先别做开机自启
手动启停足够。生产环境用 systemd 单元或 Doris Manager 托管，等你要做高可用时再学，现在做了只会多一个排查面。
:::

## 9. 报错对照表（12 个高频坑）

| 现象 / 日志关键字 | 根因 | 处理动作 |
|---|---|---|
| `Unsupported class file major version 61` | 用了 JDK 8/11 | 装 JDK 17，改 `JAVA_HOME` |
| `Could not find or load main class` | `JAVA_HOME` 路径写错 | `readlink -f $(which java)` 重新取路径 |
| FE 起一下就停，`fe.out` 里有 `priority_networks` | 网段写错或匹配不到网卡 | `ip -4 addr` 重新算 CIDR |
| `Address already in use` | 9030/8030 被占 | `ss -lntp \| grep 9030`，kill 占用进程 |
| `mysql: command not found` | 没装客户端 | CentOS 装 `mariadb`，Ubuntu 装 `mysql-client` |
| `Can't connect to MySQL server on '<IP>'` | FE 没起 / 防火墙 | 先 `ss` 确认监听，再查 firewalld |
| BE `Alive: false` | 网段不一致 / 9050 不通 / 未注册 | 6.4 节 6 步排查 |
| BE 起不来，`be.out` 里 `Cannot assign requested address` | 绑的 IP 不是本机 | 检查 `priority_networks` 是否匹配真实 IP |
| `Failed to find enough host with storage medium and tag` | 单 BE 但默认 3 副本 | 建表加 `PROPERTIES("replication_num"="1")` |
| `Too many open files` | 句柄数没生效 | 重登后 `ulimit -n` 确认 1000000 |
| `Access denied for user 'root'` | 密码已改过 | 用正确密码；忘了看 7.2 的提示 |
| 新建 FE 加不进集群（多节点时） | 时间差 > 5s | 装 chrony，`timedatectl` 确认同步 |
