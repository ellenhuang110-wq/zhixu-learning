## 1. 安装的本质，其实是六件事

装 Doris 听起来复杂，拆开看只有六件事。理解这张表，比记住命令重要十倍。

| 阶段 | 你在做什么 | 解决什么问题 | 不做 / 做错的后果 |
|---|---|---|---|
| ① 体检 | 查 CPU / 内存 / 磁盘 / 端口 / 外网 | 确认这机器**能装** | 装到一半才发现不支持 AVX2，前面的全白做 |
| ② 配系统 | 关 SELinux、调内核、建用户目录 | 让 Linux **配合**数据库 | BE 进程活着但连不上、内存抖动、句柄不够 |
| ③ 装 Java | JDK 17 | Doris 3.0 之后**必须**用 17 | FE 报 `Unsupported class file major version`，起不来 |
| ④ 摆程序 | 解压到 `/opt/doris` | 程序和数据**分开放** | 升级时把数据覆盖掉，或者和别的服务抢磁盘 |
| ⑤ 配 FE | 改 5 个参数、启动 | FE 是**大脑**：元数据、SQL、调度 | 绑错网卡、元数据丢、表名大小写不兼容 |
| ⑥ 配 BE | 改 4 个参数、注册、启动 | BE 是**仓库 + 工人**：存数据、算数据 | `Alive=false`、磁盘打满、内存被 OOM |

装完之后的日常运维，其实全是在这六件事的延长线上。

## 2. 逐步拆解：每一步到底在防什么

### 2.1 体检：为什么非要先查

| 检查 | 真正的意义 |
|---|---|
| `grep -o avx2 /proc/cpuinfo` | BE 的向量化执行引擎编译时用了 **AVX2 指令**，CPU 不支持就是 `Illegal instruction` 直接崩。这台 Xeon Gold 6326 有输出，所以用标准 `x64` 包 |
| `free -g` | 官方测试标准是 FE 8 G + BE 16 G，这台 15 G 属于"够跑实验"。更关键的是**同机还有 MySQL 占 3.8 G** |
| `df -h` | BE 的磁盘水位是**按整个挂载点算的**，不是按你的数据目录算 |
| `ss -lntp` | FE/BE 一共 8 个端口，被占了就起不来。这台 8030/8040/9030 全空 |
| `curl -I` 下载地址 | 判断能否在线装，不能就走离线传包 |

### 2.2 目录：为什么一个字节都没放 `/data`

这是本次最有价值的决策。`/data` 有 100 G 看似宽裕，但：

1. 其中 **58 G 是 MySQL 的数据**（`/data/mysql_57`），而且还会继续长；
2. BE 判断磁盘水位看的是**分区使用率**，`/data` 被 MySQL 涨到 85%，Doris 会先停写、停均衡——它不知道那是别人的数据；
3. 同机的 `xtrabackup` 全量备份也会临时吃空间，峰值不可控。

所以 Doris 全部放 `/opt/doris`（根分区），MySQL 怎么涨都影响不到它。**代价**是根分区只有 47 G，所以 BE 数据必须人为控制在 15 G 以内。

::: warning 这条经验可以带走
只要一台机器上已经有别的数据库，**不要把新数据库的数据目录放进同一个挂载点**。水位、备份、日志三者叠加，出事时你分不清是谁撑爆的。
:::

### 2.3 系统准备：每条命令防的是什么

| 配置 | 防什么 | 这次的实际情况 |
|---|---|---|
| SELinux | Enforcing 时 BE 读写数据目录被拦，表现是"进程活着但 `Alive=false`，日志没明显错误"，最难排查 | 本来就是 `Disabled`，**整步跳过** |
| firewalld | 同机其他服务访问不到 8030/9030 | 本来就 `inactive + disabled`，**跳过** |
| `swapoff -a` | 换页导致查询延迟不可控 | 本来就 `0 B` |
| THP → `madvise` | 减少内存碎片；不做会看到 BE 内存占用虚高 | 已设，但**重启会回到 `always`**，所以要写进 `/etc/rc.d/rc.local` |
| `vm.max_map_count=2000000` | BE 会做大量 mmap，默认 65530 不够 | 已生效 |
| `tcp_abort_on_overflow=1` | 连接队列满时快速失败，而不是让客户端长时间等待 | 已生效 |
| `nofile 1000000` | tablet 多了以后文件句柄不够，报 `Too many open files` | **卡在 65536，本次选择跳过**（见坑 3） |

### 2.4 为什么要单独装 JDK 17

- Doris 3.0 之后编译目标就是 JDK 17，用 8 会报 `Unsupported class file major version 61`；
- CentOS 7 的 yum 源**最高只有 java-11**，`yum install java-17-openjdk` 必然失败；
- 所以用 Corretto 17 的 tar.gz（兼容 CentOS 7 的老 glibc 2.17），解压到 `/usr/local/jdk17`，然后**在配置文件里写死路径**，不依赖系统默认 Java。

### 2.5 FE 的 5 个参数，各自管什么

| 参数 | 管什么 | 写错会怎样 |
|---|---|---|
| `JAVA_HOME = /usr/local/jdk17` | FE 用哪个 Java | 用了系统的 JDK 8，直接起不来 |
| `priority_networks = 192.168.16.0/24` | FE 用哪块网卡的 IP 对外 | 写成 IP 而不是**网段**，或者多网卡选错，BE 永远注册不上 |
| `meta_dir = /opt/doris/meta` | 元数据（库、表、用户、权限）放哪 | 放程序目录里，升级时容易一起被删 |
| `lower_case_table_names = 1` | 表名是否区分大小写（1 = 不区分，兼容 MySQL 习惯） | **建集群后不能改**，事后想改只能重装 |
| `JAVA_OPTS_FOR_JDK_17 = "... -Xms1024m -Xmx3072m ..."` | JVM 内存 | 两个值互相打架就起不来（见坑 2） |

### 2.6 BE 的 4 个参数

| 参数 | 管什么 |
|---|---|
| `storage_root_path = /opt/doris/storage,medium:HDD` | 数据放哪、介质类型（HDD/SSD 影响副本放置和迁移策略） |
| `priority_networks = 192.168.16.0/24` | BE 用哪块网卡心跳和传数据 |
| `mem_limit = 30%` | BE 内存上限。默认 80%，这台 15 G 会直接压垮 MySQL 和看板 |
| `JAVA_HOME = /usr/local/jdk17` | BE 里 Java UDF 等功能用 |

### 2.7 为什么官方要求"先 ADD BACKEND 再启动 BE"

`ALTER SYSTEM ADD BACKEND` 是**告诉 FE：待会儿会有一个 BE 来报到**。先登记，BE 一启动就能马上心跳成功；反过来先启 BE，它会反复重试注册，日志里一堆 `register to FE failed`，容易误判成故障。

### 2.8 验收为什么必须建表插入

只看到 `Alive: true` 不等于能用——那只证明心跳通了。真正的端到端验证是：**建表（元数据 OK）→ 写入（存储 + 事务 OK）→ 查询（计算 OK）**。三步都过，才叫装好了。

## 3. 这次真实踩到的 6 个坑

### 坑 1 · `fe.conf` 里根本没有 `JAVA_OPTS`

- **现象**：按清单找到"改 `JAVA_OPTS` 的 -Xmx"，`grep` 出来发现 4.0.8 里没有 `JAVA_OPTS`，只有 `JAVA_OPTS_FOR_JDK_17="..."`（一长串，带 20 多个 `--add-opens` 参数）。
- **原因**：4.x 按 JDK 版本区分配置项，JDK 8 和 JDK 17 各有一套。
- **正确做法**：改 `JAVA_OPTS_FOR_JDK_17` 里的数字，**不要新增一行 `JAVA_OPTS`**（加了也不生效，还会误导后来人）。
- **教训**：配置项名字要以**你自己机器上的文件**为准，教程可能是旧版本。

### 坑 2 · 只改了 `-Xmx`，留下 `-Xms8192m` → JVM 拒绝启动（最危险）

- **现象**：那一行变成 `-Xmx3072m -Xms8192m`，Xms 比 Xmx 还大。
- **后果**：JVM 启动直接报错退出：
  ```text
  Error occurred during initialization of VM
  Initial heap size set to a larger value than the maximum heap size
  ```
- **正确做法**：`-Xms` 和 `-Xmx` **必须一起改**，并保证 `Xms ≤ Xmx`。这台机用 `-Xms1024m -Xmx3072m`。
- **自检一条命令**：
  ```bash
  grep -o '\-Xm[sx][0-9]\+[gGmM]' fe/conf/fe.conf
  ```
  只应该出现两个值，且 Xms 不大于 Xmx。

### 坑 3 · `ulimit -n` 卡在 65536，改 `limits.conf` 无效

- **现象**：`limits.conf` 末尾加了 `* soft/hard nofile 1000000`，重新登录后还是 `65536`。
- **排查链**：
  1. `limits.conf` 开头本来就有一套**公司安全基线**：`* soft/hard nofile 65536`；
  2. `/etc/security/limits.d/` 里没有 nofile 覆盖；
  3. `systemctl show sshd -p LimitNOFILE` = `4096`，运行中的 sshd 是 `1024/4096`；
  4. 说明日志会话能到 65536 是 PAM 提上去的，而**再往上提被内核参数 `fs.nr_open` 挡住**（大概率也是 65536）。
- **本次决策**：**跳过**。单机实验的 tablet 数量远用不到 65536 个句柄，Doris 启动脚本只会打 WARN 不会拒绝启动。
- **什么时候必须回来处理**：BE 日志出现 `Too many open files`，或者要上生产多节点。

::: warning 教训
`ulimit` 不生效有两层天花板：**PAM 配置**（limits.conf / limits.d）和 **内核参数**（`fs.nr_open`）。只看第一层会一直改不对。
:::

### 坑 4 · `mysql` 客户端把日志写进了 MySQL 的目录

- **现象**：连 Doris 时出现 `Logging to file '/data/mysql_57/tmp/mysql_operation.log'`。
- **原因**：这台机用的是 MySQL 5.7 的官方客户端，它默认读 `/etc/my.cnf` 的 `[client]` 段，连**任何** MySQL 协议服务都会写日志——包括 Doris。
- **正确做法**：`--no-defaults` 放在第一个参数，完全不读 my.cnf：
  ```bash
  mysql --no-defaults -uroot -p -h192.168.16.24 -P9030
  ```
- **为什么在意**：那 58 G 是 MySQL 的地盘，别让 Doris 相关的操作往里写任何东西。

### 坑 5 · 同一台机上 `mysql` 默认连的是 3306（MySQL），不是 9030（Doris）

- **风险等级**：⚠️ 高。少写 `-P9030`，`CREATE DATABASE`、`DROP TABLE` 就打到生产/联调 MySQL 上了。`ALTER SYSTEM` 这类 Doris 专属语句在 MySQL 只会报语法错（无害），但 DDL 是真会执行的。
- **正确做法**：设别名，物理上杜绝手滑：
  ```bash
  echo "alias doris='mysql --no-defaults -uroot -p -h192.168.16.24 -P9030'" >> ~/.bashrc
  source ~/.bashrc
  ```

### 坑 6 · THP 设了 `madvise`，但重启后会回到 `always`

- **现象**：`cat /sys/kernel/mm/transparent_hugepage/enabled` 当时是 `[madvise]`，但那是运行时设置。
- **正确做法**：写进 `/etc/rc.d/rc.local`（CentOS 7）并给执行权限，才能开机生效：
  ```bash
  echo 'echo madvise > /sys/kernel/mm/transparent_hugepage/enabled' >> /etc/rc.d/rc.local
  echo 'echo madvise > /sys/kernel/mm/transparent_hugepage/defrag' >> /etc/rc.d/rc.local
  chmod +x /etc/rc.d/rc.local
  ```

## 4. 被步骤挡住的 7 个（差一点就踩）

这些这次没出事，不是因为运气，是因为清单里提前写了。

| # | 如果没做会怎样 | 是靠哪一步挡住的 |
|---|---|---|
| 1 | 单 BE 建表不写副本数 → `Failed to find enough host with storage medium and tag` | 验收步骤强制写 `replication_num=1` |
| 2 | `priority_networks` 写成 IP `192.168.16.24/24` → BE 永远注册不上 | 配置文件模板里固定成网段 |
| 3 | SELinux 开着 → BE `Alive=false`，查一天也找不到原因 | 1.2 节先 `getenforce`（这台恰好在装之前就是 Disabled） |
| 4 | `yum install java-17-openjdk` → `No package available`，然后在网上乱找 JDK | 第 2 节直接给 Corretto 压缩包 |
| 5 | CentOS 7 已 EOL，`yum install` 报 404 / 域名解析失败 | 1.1 节先换阿里云或 vault 源 |
| 6 | 用 root 启动 BE → 文件属主是 root，以后升级、备份各种 Permission denied | 强制 `su - doris`，目录 `chown -R doris:doris` |
| 7 | 数据放 `/data` 和 MySQL 抢分区 → MySQL 涨到 85%，Doris 先停写 | 0.3 节目录方案，全部放 `/opt` |

## 5. 三个最容易看错的输出

| 你看到的 | 不是你以为的意思 | 真相 |
|---|---|---|
| `SELECT version()` → `5.7.99` | 不是 MySQL 的版本，也不是连错库 | Doris 的 MySQL 协议层**固定伪装**成 5.7.99，方便 JDBC/BI 工具按 MySQL 5.7 工作 |
| `NodeRole: mix` | 不是"混合部署模式"之类 | 4.x 对 BE 节点的角色标注：`mix` = 存算一体（既存也算），单机就是这个 |
| `UsedPct: 33.81%` | 不是 Doris 用了 33% 磁盘 | 它是**所在分区**的使用率（系统 + 程序 + 看板 + Doris），Doris 自己只用了 27 KB |

查真实版本的正确姿势：

```sql
SHOW FRONTENDS\G     -- Version: doris-4.0.8-rc02-bc8ea1bac6d
SHOW BACKENDS\G      -- Version: doris-4.0.8-rc02-bc8ea1bac6d
```

## 6. 如果重来一次：最短路径

假设还是这台机（已有 JDK 目录、已有 `/opt/doris`），只要六步：

```bash
# ① 起服务（顺序不能反）
su - doris
/opt/doris/apache-doris-4.0.8-bin-x64/fe/bin/start_fe.sh --daemon
sleep 10

# ② 进 Doris（注意 --no-defaults 和 9030）
mysql --no-defaults -uroot -p -h192.168.16.24 -P9030

# ③ 看 FE
SHOW FRONTENDS\G;

# ④ 启动 BE（BE 之前已注册就不用再 ADD）
# 在另一个窗口：
su - doris && /opt/doris/apache-doris-4.0.8-bin-x64/be/bin/start_be.sh --daemon

# ⑤ 看 BE
SHOW BACKENDS\G;

# ⑥ 验收
CREATE DATABASE IF NOT EXISTS demo;
USE demo;
CREATE TABLE t1 (k1 INT, k2 VARCHAR(20))
DISTRIBUTED BY HASH(k1) BUCKETS 1
PROPERTIES ("replication_num" = "1");
INSERT INTO t1 VALUES (1,'a');
SELECT * FROM t1;
```

**日常启停**（必须 doris 用户）：

```bash
# 停
/opt/doris/apache-doris-4.0.8-bin-x64/be/bin/stop_be.sh
/opt/doris/apache-doris-4.0.8-bin-x64/fe/bin/stop_fe.sh
```

## 7. 换一台机器时，照这个清单自检

- [ ] `grep -o avx2 /proc/cpuinfo` 有输出（否则换 no-avx2 包）
- [ ] 内存 ≥ 8 G，且知道同机其他服务占多少
- [ ] 数据目录所在分区剩 ≥ 40 G，且**不与已有数据库同分区**
- [ ] 8030 / 8040 / 9030 / 9050 / 9060 没被占用
- [ ] `getenforce`（Enforcing 要先关）、`firewalld` 状态
- [ ] `swap` 是否为 0
- [ ] `java -version` 是不是 17（不是就装 Corretto）
- [ ] `fe.conf` 里 `-Xms ≤ -Xmx`，且总量给其他服务留 ≥ 3 G
- [ ] `priority_networks` 写的是**网段**
- [ ] 单 BE 环境所有建表都带 `replication_num = "1"`
- [ ] 服务用 `doris` 用户启动，不是 root

## 8. 下一步学什么

装好只是起点。按这个顺序，每一步都能直接用上：

1. **建表模型**：Duplicate / Aggregate / Unique 三选一——这是 Doris 和 MySQL 差异最大的地方，也是查得快的根源；
2. **数据导入**：Stream Load（本地文件）、Broker/Routine Load（持续导入）；
3. **备份恢复**：`BACKUP` / `RESTORE` 到远端存储，配合已有的 xtrabackup 经验理解快照；
4. **权限管理**：见 [权限管理照做清单](/doris/05-账号与安全/04-权限管理实操)；
5. **慢查询定位**：`SHOW PROC '/current_queries'`、审计日志、Profile。

## 9. 一句话记住这次

> **装的不是软件，是"把六个会互相干扰的东西排好队"**：CPU 指令集、Linux 安全策略、内存分配、磁盘归属、网卡选择、进程属主。命令只是表象，排好队才是原理。
